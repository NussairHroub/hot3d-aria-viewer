Hand annotation

One wrist pose and one angle vector, per hand per frame

HOT3D annotates a hand as a wrist transform plus a vector of joint angles, fitted to the same motion-capture ground truth as the headset and object poses. The release carries two parameterisations of that hand, UmeTrack and MANO; only UmeTrack is republished on this site. This page reads the twelve featured Aria hand files and reports what is actually in them.

What this file ships for a hand

UmeTrack

A wrist transform plus a vector of joint angles for the hand skeleton. In the hand file: wrist_t (F×3, metres), wrist_q (F×4, w·x·y·z), params (F×22, radians) and a per-frame conf, under hands.<side>.umetrack.

MANO — counted, not carried

The release's second hand parameterisation. This file keeps only its frame count, in summary.mano_frames; the pose coefficients are not republished, and summary.mano_included says so. The reason, and where to get them, is a section below.

The release stores a hand as a model, not as points: a per-participant shape profile (umetrack_hand_user_profile.json, which holds 21 landmark rest positions and their bone weights) plus, per frame, a wrist transform and 22 joint angles. The hand file here carries all of those, and also the 21 landmarks skinned from them — the forward-kinematics step the release leaves to the reader. They are drawn on the sequence viewer and in the 3D scene.

Two things worth knowing about that step. The release ships one shape profile per recording; skinned as shipped it fits the left hand exactly and the right hand not at all, so the model is mirrored through x for the right hand, with the rotation axes reflected and negated. And the check that any of this is right is the release's own 2D hand boxes: every projected landmark falls inside its hand's released box, on both hands.

Per-recording availability

A hand is annotated on a frame when the released trajectory has an entry for it; everywhere else the file stores NaN. Separately, the release gives a 2D box per hand per camera, present on the frames where that hand falls inside that camera's view. The two are independent channels rather than one nested inside the other, and the counts below measure them separately.

The box bars are drawn one per hand rather than split both / left only / right only: the summary carries each hand's box count, not the number of frames on which both hands are boxed. Frame counts come from the sequence payload and match F in the hand file.

One recording in detail

MANO: in the release, not in this file

HOT3D fits two hand parameterisations to the same motion-capture ground truth. UmeTrack is the one shown on this page. MANO is the other: the widely used parametric hand model, stored in the release as per-frame pose coefficients plus a per-participant shape vector (betas). Its frame count is kept here in summary.mano_frames; its parameters are not, because their use is gated by the SMPL-X/MANO licence, which this site cannot pass on. The counts load with the page.

Get the MANO parameters from the official release — projectaria.com/datasets/hot3D — under its own agreement, and the hand model itself from mano.is.tue.mpg.de. Because the coefficients are absent here, this page computes no comparison between the two models.

UmeTrack joint angles

UmeTrack stores the hand pose as a vector of joint angles alongside the wrist transform. The file keeps them in release order as an unnamed vector, so the rows below are numbered rather than named; each row is one angle over the whole recording.
